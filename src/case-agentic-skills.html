Agentic AI Security Skills

Why I built it

Agentic AI systems reason, call tools, keep memory and coordinate with other agents. That adds a security layer that normal application security and generic LLM checklists do not cover. Teams keep finding the same gaps:

  • Tool parameters are trusted Model-generated tool arguments are often trusted where user input would be validated, so prompt injection becomes a direct exploit.
  • Memory and retrieved content bypass filters Memory writes skip input filters, and prompt injection is defended on the user prompt but not in retrieved content.
  • Audit trails the agent can edit Logs sit in the same account the agent can write to, so a compromised agent could rewrite its own history.

What it is

  • Skills cover memory, tools and MCP, agent identity, guardrails and human approval, multi-agent trust, containment and recovery, prompt injection, testing and governance.
  • Every finding cites a real control ID from OWASP, NIST AI RMF, MITRE ATLAS, ISO 42001 or the AWS Agentic AI Lens. No invented references.
  • Findings are normalized JSON that maps to SARIF 2.1 and tracker tickets, so they fit PR comments, dashboards and audit evidence.
  • Every skill ends with a pass/fail verification test, and skills are read-only by default: they review and recommend, and never change anything on their own.
  • It works with Claude Code, Cursor, Kiro and Copilot. Role bundles chain the right skills for AI security engineers, architects, MLOps, red teamers and incident responders.

How it works

  • Install: drop the skills folder into the agent's skill path, once.
  • Invoke: ask the agent for a review, or let a PR or commit hook trigger it.
  • Report and fix: get findings with severity, control ID, evidence and a concrete fix, then re-run the verification test.

AI Security Steering Files

Short rule files that teach the Kiro AI coding assistant TUI's security standards, so the code it writes and reviews already follows them.

The problem

Kiro does not know TUI's security standards unless you give them to it. The standards are spread across different sources, so the assistant can write code that breaks a rule, and a team only finds out later in PreFlight or in a review.

What we built

Security steering is a set of short rule files that Kiro reads while you work. We went through the security standards, pulled out the rules a DevTeam has to follow and wrote them as plain instructions. Once the files are in a repo, Kiro uses them when it writes or reviews code.

How the rules are delivered

  • Always-on foundation One file is always on and covers what every repo needs, such as PreFlight, pinned dependencies and lock files.
  • By repo type The file for your repo type loads when you work in the matching folders, so Kiro only gets the rules that apply. This also keeps the assistant's context small (token-optimised).
  • On request Apigee and AWS rules are also available and load when you reference them in chat.
  • Kept current The files are kept up to date as the standards change.

What it does and does not do

It does not replace PreFlight or code review, but it should mean fewer findings when a team reaches that stage.
